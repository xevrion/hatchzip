HatchZip

解压超大压缩包，无需双倍磁盘空间。这里是 HatchZip 的官方网站，下载链接都直接指向 GitHub 上的官方发布。

HatchZip 是一款免费、开源的压缩包解压工具，支持 Windows、macOS 和 Linux，可以就地解压 ZIP、7z、RAR 和 tar 压缩包。压缩包中每一部分的文件安全写入磁盘后，它就会删除这一部分，因此只需要为解压后的文件预留空间，无需同时为压缩包和解压后的文件留出双倍空间。它提供桌面应用和命令行工具两种形式。

一个 180 GB、解压后为 200 GB 的压缩包，用 WinRAR、7-Zip 或 unzip 解压需要 380 GB 磁盘空间，因为压缩包和解压出的文件必须同时存在。HatchZip 只需略多于 200 GB：它从压缩包末尾开始解压，每解压完一部分，就把这一部分从压缩包文件中截掉，边解压边删除，空间也随之释放。

下载

Windows macOS Linux

支持 64 位 Windows 10 和 11。macOS 版本适用于搭载 Apple 芯片（M1 及更新型号）的 Mac；较旧的 Intel Mac 请下载 Intel 版本。Linux 版本为 AppImage，可在大多数发行版上运行；.deb 和 .rpm 软件包见下文。

使用方法

  1. 安装。HatchZip 目前尚未进行代码签名，因此 Windows 可能会显示“Windows 已保护你的电脑”：请点击“更多信息”，再点击“仍要运行”。在 Mac 上，先打开一次应用，然后在“系统设置”的“隐私与安全性”中允许它运行。
  2. 右键点击压缩包，选择 HatchZip，再选择 Extract here（Windows 和 Linux）。在 Windows 11 上，该菜单位于“显示更多选项”中。
  3. 也可以打开 HatchZip 应用，打开压缩包或把它拖到窗口上，然后选择“解压”。

HatchZip 会在开始解压前告诉你文件能否放得下。压缩包会随着文件解压出来而逐步删除，因此解压完成后，只剩下解压出的文件。

也可以在终端中安装。Linux 和 macOS：

curl -fsSL https://raw.githubusercontent.com/xevrion/hatchzip/main/install.sh | sh

Windows（在 PowerShell 中）：

irm https://raw.githubusercontent.com/xevrion/hatchzip/main/install.ps1 | iex

如果已安装 Rust，也可以运行 cargo binstall hatchzip 下载发布版本，或运行 cargo install hatchzip 从源代码构建。

然后运行 hatchzip check game.zip 查看能否放得下，运行 hatchzip extract game.zip 进行解压。也可以使用简短的命令名 hz，man hatchzip 提供完整手册。

功能

  • 解压 ZIP（包括 ZIP64 和自解压 .exe 文件）、7z、普通 tar、.tar.gz、.tgz、.tar.bz2、.tbz2、.tbz、.tar.xz、.txz、.tar.zst 和 .tzst，以及 ZIP 或 7z 的分卷压缩包（.001、.002、...）。
  • 解压 RAR 5 和 RAR 4，包括单个文件和分卷（.part1.rar、... 或 .rar、.r00、...），逐个文件释放压缩包占用的空间，每个分卷清空后即删除，也支持用“加密文件名”选项创建的压缩包。固实 RAR 只能在保留压缩包的情况下解压。RAR 支持包含在本网站和发布页面提供的下载文件中，通过 cargo install hatchzip 安装的版本不包含 RAR 支持。
  • 压缩的 tar 包（.tar.gz、.tar.bz2、.tar.xz 或 .tar.zst）会在开始解压前从头到尾完整读取一遍，因此损坏的压缩包会被拒绝，且保持原样。之后，在 NTFS（Windows）、APFS（macOS）、ext4、XFS、btrfs 以及其他支持释放文件部分空间的文件系统上，它会边解压边释放空间。在 FAT32 和 exFAT 上它仍然可以解压，中断后也能继续，但需要能同时容纳压缩包和文件的空间。
  • 在开始解压前，先检查解压后能否放得下。
  • 在开始解压前，在应用中以文件夹树的形式显示压缩包内容，并显示各文件夹的大小。
  • 桌面应用提供英语、西班牙语、印地语和简体中文界面，默认跟随系统语言，也可以在“设置”的“语言”中选择其他语言。
  • 桌面应用的所有选项都集中在一个“设置”窗口中，可以从“文件”菜单、窗口右上角的齿轮图标或 Ctrl+,（Mac 上为 Command+,）打开。其中包括语言和外观、解压完成后的操作、是否在解压时删除压缩包、预留空间、默认目标位置、文件已存在时的处理方式，以及右键菜单。
  • 空间足够同时容纳两者时，也可以常规解压并保留压缩包：使用 --keep-archive、应用中的选项，或右键菜单中的 Extract here (keep archive)。如果保留压缩包放不下，它会告诉你改用就地解压需要多少空间。
  • 可以依次解压多个压缩包，每个开始前都会检查所需空间。一旦某个压缩包未能完成，整个任务就会停止，并列出哪些已解压、哪些未解压。
  • 使用 hatchzip extract --nested 时，还会解压它写出的文件中的压缩包，只深入一层，每个都解压到其旁边的文件夹中。只有扩展名和文件内容都表明是压缩包的文件才会被当作压缩包，因此 .jar 或 .docx 文件不会被处理。它会先列出这些压缩包，并在解压前只询问一次；--yes 可跳过询问。此功能仅在命令行工具中提供。
  • 可以只解压需要的内容：在应用的内容列表中按住 Ctrl 或 Command 点击、按住 Shift 点击或按空格键选择文件或文件夹，再选择“解压所选项”，或者使用 hatchzip extract game.zip --only game/saves。部分解压时，压缩包始终会被保留。
  • 默认预留 2 GB 可用空间，确保磁盘不会被完全占满。可以用 --keep-free 修改，也可以在应用设置的“预留空间”中修改。
  • 随时可以用 Ctrl+C 停止，即使中途崩溃也不要紧。再次运行同一条命令，它会从中断处继续。
  • 解压时逐个检查文件的 CRC-32。遇到损坏的文件会停止解压，该文件仍保留在压缩包中。
  • 如果压缩包旁边有与其同名的 .sfv 文件，会在开始解压前用它校验每个分卷。
  • 从不覆盖已存在的文件，因此“解压到此处”是安全的。
  • 可以打开有密码保护的 ZIP、7z 和 RAR 压缩包。它会在删除任何内容之前验证密码，并且从不保存密码。
  • 适用于任何能够缩短文件的文件系统：ext4、btrfs、XFS、NTFS、APFS，以及 exFAT 和 FAT32 格式的 U 盘。

实测结果

同样的 200 MB 游戏数据（21 个文件），分别用相应的真实工具打包，在一个只剩约 50 MB 可用空间的 220 MiB 磁盘上解压：

压缩包unzip / 7-ZipHatchZip
ZIP，180 MBunzip 解压到第 6 个文件（共 21 个）时空间不足完成，每个文件逐字节一致
7-Zip 25.01 创建的 7z，-ms=20m（10 个固实块）需要 380 MB0.64 s 完成，每个文件逐字节一致
分为 5 个 40 MB 分卷的 7z需要 380 MB完成；分卷逐个删除，峰值占用 210 MB
GNU tar 创建的 tar，200 MB需要 400 MB0.12 s 完成，每个文件逐字节一致
7-Zip 默认设置创建的 7z（1 个固实块）需要 380 MB未做任何改动即拒绝：单个固实块必须全部解压出来后才能释放，因此需要 200 MB 可用空间

同样数据的 ZIP 解压耗时 0.25 到 0.35 s（其中包括 unzip 省略的一次 fsync），而 unzip 6.00 需要 1.48 到 1.50 s。为测试崩溃安全性，在每种格式解压过程中的许多时间点，分别在每个批次最易出问题的两个时机强制终止进程；每次继续解压后的输出都完全一致。

测试环境：Fedora 43，Intel Core i7-14700HX，SK Hynix NVMe SSD，页面缓存已预热；磁盘空间测试使用 220 MiB 的 tmpfs 模拟空间已满的笔记本电脑磁盘，速度测试使用 ext4。速度提升来自并行解压多个文件，因此只包含一个超大文件的压缩包只能以单核速度解压。

限制

  • 用 7-Zip 默认设置创建的 7z 可能只有一个固实块。HatchZip 只有在这个块全部解压出来后才能释放它，因此需要能容纳整个块的可用空间。hatchzip check 会在开始解压前告诉你。
  • 以单个帧创建的 .tar.zst（即使使用 -T0，zstd 命令生成的也是这种文件），或者帧中没有校验和的 .tar.zst，只能在保留压缩包的情况下解压：使用 --keep-archive，或在应用中关闭“解压时逐步删除压缩包”。用 pzstd 创建、采用可寻址（seekable）格式或由多个文件拼接而成的 .tar.zst 包含多个帧，会边解压边释放空间。
  • 以单个块创建（xz -T1 生成的就是这种）或没有完整性校验的 .tar.xz，只能在保留压缩包的情况下解压。
  • 固实 RAR 只能从头到尾一次性解码，因此无法边解压边释放空间；只能在保留压缩包的情况下解压。包含符号链接或硬链接的 RAR 压缩包会在解压前被拒绝；加密了文件名的 RAR 压缩包在部分解压后无法恢复，只能继续完成解压。
  • 压缩包会在解压过程中逐步删除。如果下载的文件本身已损坏，损坏位置之前的文件会被解压出来，而压缩包已被部分删除。如果无法重新下载，请使用 --verify-first。

常见问题

HatchZip 安全吗？

HatchZip 会在开始解压前检查解压后能否放得下。每个文件都会先写入并刷新到磁盘，然后才截掉压缩包中存放它的部分，因此即使崩溃，每个文件要么已经解压出来，要么仍在压缩包中。每个文件的 CRC-32 都会经过校验，遇到损坏的文件会停止解压。如需确认下载的文件是否为官方原版，请参阅校验下载文件（英文）。

HatchZip 需要联网吗？

不需要。HatchZip 没有任何网络代码和网络库，没有遥测，也没有账户，从不自行检查更新。它读取磁盘上的压缩包，并把文件写到压缩包旁边。如果依赖项中引入了 HTTP、TLS 或 socket 库，它的 CI 就会失败。桌面应用中只有两个链接，分别指向源代码和最新版本（位于“帮助”菜单的“检查更新”），都会在你的浏览器中打开。

HatchZip 能解压哪些压缩格式？

HatchZip 可以解压 ZIP（包括 ZIP64 和自解压 .exe 文件）、7z、RAR 5 和 RAR 4、普通 tar、.tar.gz 和 .tgz、.tar.bz2、.tbz2 和 .tbz、.tar.xz 和 .txz、.tar.zst 和 .tzst、ZIP 或 7z 的 .001 分卷压缩包，以及 RAR 分卷。它可以打开有密码保护的 ZIP、7z 和 RAR 压缩包。固实 RAR 只能在保留压缩包的情况下解压；以单个帧创建的 .tar.zst 也是如此，而 zstd 命令默认生成的就是这种文件。

HatchZip 需要多少可用空间？

HatchZip 所需的空间约等于解压出的文件大小，再加上它一次能释放的最大部分：ZIP、tar 和 RAR 为一个文件，7z 为一个固实块。一个 180 GB、解压后为 200 GB 的压缩包，只需略多于 200 GB，而不是 380 GB。它默认还会预留 2 GB 可用空间。hatchzip check 会显示确切数字，且不做任何改动。

HatchZip 崩溃或被中止会怎样？

HatchZip 会把进度保存在压缩包旁边的几个小文件中。遇到崩溃、断电或按下 Ctrl+C 后，在应用中打开同一个压缩包，或再次运行同一条命令，它就会从中断处继续。如果想放弃解压，hatchzip restore 会把剩下的部分恢复为普通压缩包，其中包含尚未解压的文件。

HatchZip 能在 FAT32 和 exFAT 磁盘上使用吗？

可以。ZIP、7z、tar 和 RAR 压缩包通过缩短压缩包文件来释放空间，这在所有文件系统上都可行，包括 FAT32 和 exFAT 格式的 U 盘。压缩的 tar 包（.tar.gz、.tar.bz2、.tar.xz 或 .tar.zst）只有在文件系统支持释放文件部分空间时（例如 NTFS、APFS、ext4、XFS 和 btrfs），才能边解压边释放空间。在 FAT32 和 exFAT 上它仍然可以解压，但需要能同时容纳压缩包和文件的空间。

  • 磁盘空间不足，无法解压 ZIP、RAR 或 7z：原因和各种解决方法，附实测。
