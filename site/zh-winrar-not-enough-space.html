WinRAR 明明有空间却提示磁盘空间不足的原因

如果解压的目标磁盘还有空间，先看看 WinRAR 实际把文件写到了哪里。从 WinRAR 窗口中拖出文件，或者直接打开压缩包里的文件时，WinRAR 会先把文件解压到 Windows 临时文件夹，而它通常在 C: 盘。FAT32 格式的 U 盘无法存放 4 GiB 及以上的单个文件。请改用 Extract To（解压到），并检查磁盘的文件系统。

作者：Yash Bavadiya，HatchZip（英文）的开发者。更新于 2026-11-20。

“Not enough disk space”和“There is not enough space on the disk”是什么意思？

两者都表示某次写入失败了，原因是某个磁盘已满，或者无法容纳这个文件。出问题的不一定是你选择的那个磁盘。

WinRAR 自己的相关提示包括“Not enough disk space for”加文件名，以及“Write error in the file”（两者都出自 WinRAR 7.13）。“There is not enough space on the disk.”（中文版 Windows 显示为“磁盘空间不足。”）是 Windows 系统错误 112 的提示文字，见 Microsoft 的列表。如果提示中带有路径，看看它位于哪个磁盘：要检查的就是那个磁盘。

为什么解压到其他磁盘时，WinRAR 会把 C: 盘占满？

因为拖放操作以及直接打开压缩包中的文件，都要经过 Windows 临时文件夹。WinRAR 帮助的常见问题列表在谈到它遗留的临时文件时，明确说明了这一点（译文）：“使用拖放来解压文件，或者用外部查看器打开压缩包中的文件时，就会出现这种情况。”

所以，当你把一个很大的文件夹从 WinRAR 窗口拖到 D: 盘时，临时文件夹所在的磁盘必须先有足够的空间容纳它。要查看临时文件夹的位置，在文件资源管理器的地址栏中输入 %TEMP%。在标准的 Windows 环境中，它位于 C: 盘上你的用户文件夹内。WinRAR 在那里创建的临时文件夹，名称以 Rar$ 开头。

WinRAR 不会立即删除这些文件夹。它的帮助中写道，WinRAR 下次启动时，会删除创建超过一个小时的临时文件。在此之前，一次失败的拖放所留下的 Rar$ 大文件夹，可能仍然占用着 C: 盘的空间。

解决方法：Extract To（解压到）

在 WinRAR 中选中文件，点击 Extract To（解压到），或按 Alt+E，然后选择目标文件夹。也可以在文件资源管理器中右键单击压缩包，使用 WinRAR 的某个解压菜单项。WinRAR 帮助指出，使用 Extract To（无论是在窗口中还是在右键菜单中）可以完全不经过临时文件夹。

相关设置：临时文件夹

WinRAR 还有一项设置，位于 Options（选项）、Settings（设置）、Paths（路径）下，名为 Folder for temporary files。它的帮助页面（英文）说明，这是 WinRAR 用来创建临时文件的文件夹；该文件夹必须已经存在，输入 %temp% 可恢复为 Windows 默认位置。帮助中没有列出哪些命令会使用它，因此如果修改后 C: 盘仍然被占满，请使用 Extract To。

FAT32 格式的 U 盘会导致这个错误吗？

会。无论 U 盘还剩多少空间，FAT32 都无法存放 4 GiB 及以上的单个文件。Microsoft 的文件系统功能比较列出 FAT32 的最大文件大小为 4 GiB，而 exFAT 和 NTFS 为 264 字节减 1。

新版 WinRAR 对这种情况有专门的提示：WinRAR 7.13 中包含“FAT32 file system does not support 4 GB or larger files”。其他程序可能只显示普通的空间不足错误；Microsoft 社区论坛上 2026 年 7 月的一个提问（英文）反映的正是这种情况：向 U 盘复制大文件时出现空间不足错误。

要检查文件系统，在文件资源管理器中右键单击该磁盘，选择“属性”，查看“文件系统”一项。要解决这个问题，先把磁盘上需要的文件复制出来，再将它格式化为 exFAT 或 NTFS：右键单击该磁盘，选择“格式化”，然后选择文件系统。格式化会清除磁盘上的所有数据。

磁盘配额或 C: 盘已满会是原因吗？

会，有两种情况。

  • 磁盘配额。在由公司或学校管理的电脑上，管理员可以限制每个帐户在 NTFS 磁盘上能使用的空间。Microsoft 关于 GetDiskFreeSpaceEx 的文档指出，启用按用户配额时，你可用的空间“可能少于磁盘上的总可用字节数”。请咨询这台电脑的管理员。
  • C: 盘已满。如果 C: 盘快满了，由于上文所说的临时文件夹，无论把文件拖放到哪里，每次从 WinRAR 拖出文件都可能失败。请使用 Extract To，或者释放 C: 盘空间。

如果压缩包和解压出的文件确实放不下怎么办？

那 WinRAR 的提示就没错：在解压结束之前，磁盘必须同时容纳压缩包和所有解压出的文件。把 WinRAR 文件列表中 Size 一列的数值加起来，就能知道它要写入多少数据；Packed 一列则是压缩包本身已占用的空间。

解决方法有三种：解压到其他磁盘、释放空间，或者就地解压。磁盘空间不足时如何解压的指南逐一介绍了这些方法，并附有在几乎已满的磁盘上的测试。

HatchZip 能解决什么，不能解决什么

HatchZip 只能解决最后一种原因。它可以就地解压 RAR 5 和 RAR 4 压缩包，包括单个文件和 .part1.rar 这样的分卷压缩包：它会逐个文件地释放压缩包占用的空间，并在每个分卷清空后将其删除，因此磁盘只需容纳解压出的文件，而不必同时容纳这些文件和压缩包。下载 HatchZip；从本站下载的版本已包含 RAR 支持。

以下情况它无能为力：

  • 临时文件夹。这是 WinRAR 把文件交给文件资源管理器的方式，并不是目标磁盘空间不足。请使用 Extract To。
  • FAT32。HatchZip 同样无法向 FAT32 磁盘写入 4 GiB 及以上的文件。请将磁盘格式化为 exFAT 或 NTFS。
  • 磁盘配额留给你帐户的空间少于文件所需的空间。
  • 固实 RAR。它只能从头到尾一次性解码，因此 HatchZip 只能在保留压缩包的情况下解压它，所需空间与 WinRAR 相同。
  • 加密了文件名或包含链接的 RAR 压缩包。HatchZip 会在开始解压前拒绝处理它们。
  • 保留压缩包。就地解压会把压缩包消耗掉。
